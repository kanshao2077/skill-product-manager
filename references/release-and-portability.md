# 发布与可移植性

只在目标 Skill 要供团队复用、跨 Agent 安装或公开发布时读取。创建 Skill 的授权不自动包含发布授权。

## 1. 先定义发布目标

明确：

- 目标用户和宿主：Codex、Claude、其他支持 `SKILL.md` 的 Agent，还是指定商店。
- 源码真相：哪个目录是平台中立的主版本。
- 分发物：GitHub 仓库、ZIP、`.skill`、商店专用包或本地安装。
- 所有者、许可证、版本号、公开可见范围和更新方式。

不要承诺“所有 Agent 一键可用”。只能声明已实际验证的宿主；其余写明所需能力和可能的适配步骤。

## 2. 保持平台中立核心

- 根 `SKILL.md`、`references/`、`scripts/` 和 `assets/` 使用相对路径。
- 把宿主专属 UI 元数据放在独立适配层，例如 `agents/openai.yaml`；不要让它成为核心运行依赖。
- 某平台不接受特定元数据时，生成目标专用包或过滤清单，不要从通用源码中永久删掉其他平台需要的文件。
- 脚本写清运行时、最低版本、网络和权限要求；能用标准库时不引入大依赖。

## 3. 共享或公开 README

README 面向第一次安装的人，至少包含：

1. 一句话能力与明确不能做什么。
2. 需要宿主具备的工具、网络、账号或本地运行时。
3. 安装、调用和验证步骤。
4. 完整目录结构及各文件用途。
5. 一个可复制的真实例子。
6. 常见失败、更新方式、隐私与数据边界。
7. 已验证平台与尚未验证平台。

README 是给人看的产品页，不应被复制进运行时 `SKILL.md`。

## 4. 发布前门禁

至少检查：

- 根入口、frontmatter、引用路径、脚本运行和行为用例均通过。
- 版本、标签、包名、README 示例和安装命令一致。
- 没有密钥、Cookie、Token、私人路径、原始私聊、未授权素材或临时测试产物。
- 第三方内容的许可证和署名义务已落实；无许可证内容只吸收高层机制，不复制正文或代码。
- 在干净临时目录做一次安装，并用公开包而非本地源码完成最小调用验证。
- 远端默认分支、Release 文件和公开 README 可实际访问；仅有仓库 URL 或 push 成功不算发布完成。

## 5. 外部动作审批

正式写入 GitHub、SkillHub 或其他平台前，展示一份精简 payload：

```text
名称 / 技术 ID / 版本：
目标平台与可见范围：
源码或包路径：
将包含 / 排除的文件：
许可证与署名：
已完成验证：
仍缺证据：
将执行的远程动作：
```

等待用户明确说“提交”“确认发布”或等价表述。创建、测试、打包、dry-run、登录检查都不能替代这次确认。

发布后验证远端内容、版本和干净安装；失败就报告实际状态，不把“已发起”写成“已完成”。
